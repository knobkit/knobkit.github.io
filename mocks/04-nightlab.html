Declare widgets, write event handlers — done. The same file runs entirely in the browser, or with handlers on a stateless Node server. Swap one line.

$ npm create knobkit@latest⌘C
demo.tsx
import { knobkit, text, button, output } from "knobkit"; const name = text({ placeholder: "Ada" }); const greet = button({ label: "Greet" }); const out = output(); const app = knobkit({ widgets: [name, greet, out] }); app.on(greet.clicked, async () => { const who = (await name.value()).trim() || "world"; out.set(`Hello, ${who}!`); }); app.serve(); // ← or app.mount("#root")

The browser owns all state

The server keeps nothing. Handlers pull what they read, send structured edits back. Restart, redeploy, scale — nobody's app breaks.

One file, two tiers

Prototype client-side — WebGPU models included — then move handlers to Node for secrets and big models by changing the last line.

Events, not reruns

Plain on(event, fn) handlers. No full-script re-execution per click, no reactive graph to fight, no widget-key gymnastics.
