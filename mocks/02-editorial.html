knobkit.

Your AI app, live as you type — widgets in, handlers on, nothing else.

declare → handle → serve( ) | mount( )  ·  the browser owns the state

№ 01

The browser owns all state.

A knobkit server keeps nothing. Handlers pull the attributes they actually read and write back structured edits. Restart, redeploy, scale — no one's app breaks.

№ 02

One file, two tiers.

Prototype entirely in the browser — WebGPU models included — then move handlers to a server when you need secrets or big models, by changing the last line.

№ 03

Events, not reruns.

Handlers are plain on(event, async fn) functions. No full-script re-execution on every click, no reactive graph to fight, no widget-key gymnastics.

№ 04

Data stays where it lives.

A request crossing the wire is just { type, payload } — never a copy of state. An attribute a handler never reads never leaves the browser.

import { knobkit, chat } from "knobkit";

const convo = chat({ placeholder: "Say something…" });

const app = knobkit({
  title: "Echo bot",
  widgets: [convo],
});

app.on(convo.sent, async ({ text }) => {
  convo.say({ role: "user", content: text });
  convo.say({
    role: "assistant",
    content: [...text].reverse().join(""),
  });
});

app.serve(); // ← the only line that changes

Same authoring feel as Gradio or Streamlit.
Different architecture.1

Declare inputs, write a function, get an app — but with plain events instead of reruns, and a server that holds no sessions, no sticky state, no memory of you at all.

1 Thirty-plus widgets: chat, mic, webcam, code, table, chart, upload, gallery, audio, video, sliders, sandboxed frames — and custom() when those run out.
